# 规格说明书 (Spec) — 2048 RL 训练实验平台 MVP

> 阶段：G0 Requirement ｜ 状态：✅ Approved（2026-06-07）｜ 负责人：唯一工程师 ｜ 日期：2026-06-07
> 输入：artifacts/requirements/raw-requirement.md

## 1. 背景与目标

- **业务背景**：为客户搭建强化学习训练平台（多智能体协同控制方向）做技术可行性验证。客户要求先看到一个**可运行的 Demo**。技术负责人选定 2048 游戏作为 MVP 训练场景（纯 Python、零外部仿真器依赖、30 分钟~2 小时收敛、策略区分度好、结果直观）。
- **核心目标**：交付一个**可一键启动、可复现、有测试支撑**的 2048 RL 训练实验平台 MVP，能够训练出明显优于随机/贪心基线的 Agent，并通过可视化界面展示训练过程与实验对比。
- **成功指标（Success Metrics）**：
  - **S1（可复现）**：`README.md` 启动步骤可在 **5 分钟内**完成环境拉起并开始训练。
  - **S2（智能性）**：训练后的 Agent 在评估时，**最大方块中位数 ≥ 512**（明显高于随机策略基线），作为"Agent 在变聪明"的量化证据。〔阈值需人类确认，见 A-3〕
  - **S3（可观测）**：每次训练自动产出配置、reward 曲线、检查点，且可在可视化界面查看与跨实验对比。
  - **S4（正确性）**：核心环境逻辑（合并、移动、得分、终局判定）有自动化测试覆盖且全部通过。

## 2. 范围（In Scope）

- **R1 环境**：从零实现 2048 游戏环境，符合 Gymnasium 标准接口（`reset` / `step` / `render`），含标准 `observation_space` / `action_space` / `reward` / `done` / `info`。
- **R2 算法**：实现**至少一种** RL 算法（DQN 或 PPO，本期默认 **DQN**，见 A-2），超参数通过配置文件（YAML）管理。
- **R3 实验记录**：训练过程自动记录实验配置、训练指标（至少 reward 曲线，建议含 max-tile、episode 长度）、模型检查点（按周期 + 最优保存）。
- **R4 可视化**：提供界面查看训练曲线、对比不同实验（默认采用 **TensorBoard**，见 A-4）。
- **R5 一键启动**：提供一键启动方式（脚本 + Docker 二选一或均提供，见 A-5），覆盖训练、评估、可视化。
- **R6 测试**：提供自动化测试证明系统正确性（环境逻辑为重点，训练链路提供冒烟测试）。
- **R7 文档**：`README.md` 含 5 分钟内可复现的启动步骤、开源引用来源说明。

## 3. 非目标范围（Out of Scope）

- ❌ 多智能体协同控制本身（本期仅单 Agent 单环境的 2048 MVP，多智能体是平台长期方向，非本期）。
- ❌ 分布式 / 多机并行训练、GPU 集群调度。
- ❌ SOTA 性能调优、必达 2048 方块（目标是"明显变聪明"而非刷分上限）。
- ❌ 生产级 Web 平台（用户系统、权限、数据库、云部署、CI/CD 流水线）。
- ❌ 多种算法横向对比（本期只要求至少一种；第二种算法为可选增强）。
- ❌ 超参数自动搜索（HPO / sweep）。
- ❌ 实时在线推理服务 / 对外 API。

## 5. 非功能需求

- **性能**：单台 Apple M2 笔记本（CPU，可选 MPS）在 30 分钟~2 小时内观察到收敛趋势；quick 配置分钟级跑通管线。
- **可复现性**：支持随机种子；同种子同配置结果可复现；启动 ≤ 5 分钟。
- **可维护性**：环境 / 算法 / 训练 / 记录 / 可视化模块解耦；代码仅写入 `src/`。
- **可观测性**：训练日志含 step、reward、max-tile、loss、ε 等关键指标。
- **可移植性**：依赖锁定（requirements.txt / 版本固定）；Docker 化保证环境一致。
- **安全**：本地工具，无对外服务，无敏感数据；仅需注意依赖来源可信。

## 8. 边界条件（Edge Cases）

- 棋盘已满但仍可合并 → 非终局；棋盘满且四方向均不可合并 → 终局（done）。
- 某方向无法移动（非法动作）→ 棋盘不变，按 A-8 处理。
- 新方块生成概率（经典规则 2 占 90%、4 占 10%）→ 需可配置随机种子以复现。
- reward 数值范围与归一化 → 防止数值爆炸影响训练稳定。
- 检查点写入时磁盘满 / 路径不存在 → 需健壮的目录创建与异常处理。
- 训练中断后恢复 → 是否支持 resume（本期至少保证检查点不丢，resume 为 P1）。
- 评估时加载与训练不一致的网络结构 → 需校验配置一致性。
- 空实验目录 / 首次启动 TensorBoard 无数据 → 界面应优雅显示空态。
- 极长 episode（步数无上限）→ 需 `truncated` 步数上限防止卡死。

## 9. 风险（Risks）

| 编号 | 风险描述 | 等级 | 缓解措施 |
| ---- | -------- | ---- | -------- |
| R-1  | RL 训练不收敛 / Agent 学不出（2048 稀疏奖励、探索难） | High | 合理 reward 设计、obs 归一化、调小问题规模先验证管线、提供已验证默认超参；先用随机基线对照 |
| R-2  | "5 分钟内可复现"在不同机器上难保证（依赖/版本漂移） | High | Docker 锁定环境 + requirements 固定版本 + 最小化首启动训练步数验证管线 |
| R-3  | 训练耗时与"30 分钟~2 小时"预期不符（取决于硬件） | Medium | 提供 quick/full 两套配置；默认 quick 验证可行性，full 追求效果 |
| R-4  | 从零实现 2048 逻辑出现合并/计分 bug，污染训练 | Medium | 环境逻辑高覆盖单测（移动、合并、计分、终局），TDD 优先 |
| R-5  | 单工程师 + MVP 时间紧，范围易蔓延 | Medium | 严守非目标范围；第二种算法/GUI/resume 列为 P1 可选 |
| R-6  | gymnasium 版本 API 差异导致接口不合规 | Medium | 锁定 gymnasium 版本，按新版 5 元组实现并加接口一致性测试 |
| R-7  | 引用开源代码未注明来源（合规要求） | Low | Review 阶段强制核对，README 标注所有引用来源 |

## 10. 依赖与约束

- **运行环境**：**Python 3.10.11**，**Apple M2（ARM64，macOS）单机**，无 NVIDIA GPU（PyTorch 用 CPU/MPS，非 CUDA）。
- **外部依赖**：Python 3.10.11、`gymnasium`、**PyTorch（CPU/MPS 版）**、`numpy`、`tensorboard`、`pyyaml`；Docker（可选，需 arm64 兼容基镜像）。
- **技术约束**：纯 Python、环境从零实现、零外部仿真器依赖；代码只写入 `src/`，文档只进 `artifacts/`。
- **流程约束**：遵守 G0→G4 门控；所有 AI 生成代码须经人工 Review 并记录；开源引用须注明来源。
- **交付约束**：提交完整仓库；README 启动步骤 5 分钟内可复现。
